5. GDPval-AA

经济工作价值评估（Agentic Elo）

2025-09 Knowledge Work
全称
GDPval-AA = OpenAI GDPval dataset + Artificial Analysis 评测框架
创建者
OpenAI（数据集，2025-09-25）+ Artificial Analysis（评测 harness + Elo 排名）
论文链接
OpenAI GDPval | arXiv:2510.04374 | AA Leaderboard
评测能力
经济上有价值的真实知识工作：跨职业、跨行业的专业交付物（非学术考试答案）
数据规模
1,320 个专业任务（220 个 gold set 开源）| 44 个职业 x 9 个美国 GDP 顶级行业
评分方式
Agentic loop (shell + 浏览器 via Stirrup) → 盲评 pairwise comparison → Elo Rating

设计特色

  • 非学术考试：评估真实工作产出（报告、分析、代码、方案），而非选择题
  • Agentic 评测：模型有 shell 和浏览器工具，模拟真实知识工作者的工具环境
  • Elo 排名：通过盲评对比计算动态 Elo，比单纯准确率更能反映综合质量
  • 覆盖行业：科技、金融、法律、医疗、制造、零售、教育等

7. SWE-fficiency

代码性能优化评测 — Pass-to-Pass 而非 Fail-to-Pass

ICLR 2026 Efficiency
全称
SWE-fficiency: Can Language Models Optimize Real-World Repositories on Real Workloads?
创建者
Harvard + Google DeepMind + Princeton + Xi'an Jiaotong
Jeffrey Jian Ma, Milad Hashemi, Amir Yazdanbakhsh, Kevin Swersky, Ofir Press 等
发布日期
OpenReview 2025-09-17 → 修订 2026-02-11 → ICLR 2026
论文链接
OpenReview | GitHub | swefficiency.com
评测能力
仓库级性能工程：找到瓶颈、让代码更快、同时保持正确性（非 Bug 修复）
数据规模
498 个任务，来自 9 个主流 Python 库：numpy, scipy, pandas, scikit-learn, matplotlib, xarray, sympy, dask, astropy
评分方式
Speedup Ratio (SR) = LM speedup / expert speedup，调和平均聚合
SR > 1 意味着超越人类专家优化

与 SWE-bench 核心区别

维度SWE-benchSWE-fficiency
任务类型Fail-to-Pass（修 Bug）Pass-to-Pass（优化性能）
核心指标能否通过测试加速比 vs 专家优化
代码状态有 Bug正确但慢
考察重点理解 + 修复Profiling + 算法优化 + 底层调优
实际意义能否修好代码能否写出生产级高效代码

评测设置（MiniMax M3 报告）

参数值
Sandbox1C2G (1 CPU core, 2GB RAM)
Timeout2 小时
ScaffoldingClaude Code
MiniMax M3 分数34.8%
注意：原论文报告当时最佳 Agent 平均 SR < 0.15x 专家水平。 MiniMax M3 的 34.8% 可能是 SR 百分比化表示（即 0.348x 专家水平），尚需确认口径。
与 Auto Research 的关联： 64 卡 GPU 环境下，代码效率直接影响实验周期。DataLoader 瓶颈、内存泄漏、低效 tensor 操作 都会浪费宝贵算力。SWE-fficiency 评估的正是"让已有代码跑得更快"的能力 — 这是我们 Agent 迭代优化阶段的关键技能。数据来源涵盖 numpy/scipy/pandas， 与 ML 训练代码高度相关。

关键洞察

  • 模型选择：Opus 4.8 在 6/9 个 Benchmark 上排名第一，是当前最全面的 Agent 后端
  • Harness 重要性：Terminal-Bench 证明 scaffold/harness 对分数影响巨大（同模型差 5-10pp）， 我们的 LangGraph 编排质量直接影响 Agent 上限
  • Tools 加成：HLE 证明工具增强能提升 8-11pp，验证了我们"Agent + 工具"的设计方向
  • 效率是新前沿：SWE-fficiency + KernelBench 标志着评测从"能做到"转向"做得又对又快"
  • MCP 成为标准：MCP Atlas 的出现说明 MCP 已成为 Agent 工具使用的标准协议层

建议：纳入我们评测体系的 Benchmark

里程碑评测方式目的
M2 (W4) 自建 Mini-Terminal-Bench (10-15 tasks, Slurm 环境) 验证 Agent 基本终端操作能力
M3 (W6) 自建 CV-SWE-bench (20 tasks, 从真实 CV repo PR 构建) 验证代码修改能力
M4 (W8) MLE-bench subset + 自建 metric (mAP/mIoU 提升率) 验证端到端 ML 实验能力
M5+ (W10+) KernelBench (标准版) + 训练效率测试 Agent 能否优化训练代码性能
