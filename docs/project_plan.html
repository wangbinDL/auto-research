1. 项目背景与动机

1.1 一句话说清楚我们要做什么

我们要造一个能自动做科研的 AI 系统（目标检测/语义分割领域），然后把它"解题的完整思路"录制下来，作为训练下一代大模型的教科书数据。最终用这些数据训练一个 Qwen 模型，使其在 CV 科研任务上接近 Codex / Claude Code 的科研能力水平。

1.2 为什么做这件事？

2026 年，大模型最稀缺的不再是普通问答数据，而是长程决策轨迹数据——即 AI 面对一个复杂问题时，从头到尾"怎么想、怎么试、失败了怎么改、最后怎么成功"的完整过程记录。

对标参考——Codex / Claude Code：

Claude Code 在 SWE-bench 上从 22%（2024.03）飙升到 72.5%（2025.05），18 个月翻了 3 倍。Codex 在同期达到类似突破。能力爆发的核心原因不是工具多，而是训练数据的进化——从普通代码数据升级为"完整的编程决策轨迹"。

我们的目标：在 CV 科研领域复现这个范式——用"科研决策轨迹"训练模型，让它在目标检测/语义分割任务上达到接近 Codex/Claude Code 级别的自主研究能力。

2. 一个故事讲清楚整件事

想象你是一位 CV 研究员，面前有一个目标检测任务需要提升 mAP。你会怎么做？

第一步：观察现状。你跑了一个 baseline 模型，看到 mAP 只有 38.2%。你分析了 bad case——小目标漏检严重。

第二步：提出假设。"如果我把 anchor 尺寸改小、同时加一层 FPN，小目标应该能好。"

第三步：写代码改配置。你修改了 config 文件，调了 anchor size，加了 FPN level。

第四步：跑实验。提交训练任务，等 2 小时，mAP 涨到 40.1%。

第五步：分析结果。小目标好了，但大目标退化了。你决定加一个 multi-scale 训练策略。

第六步：继续迭代……

上面这个过程——观察→假设→修改→实验→分析→再迭代——就是一条完整的"科研决策轨迹"。

我们要做的事情，就三步：

① 造一个能自动做上述事情的 AI Agent（代替你坐在电脑前反复操作）
② 把 Agent "解题的全过程"录制下来（每一步想了什么、改了什么、结果如何）
③ 用这些"解题过程"训练一个新模型（让 Qwen 学会像你一样做科研）

2.1 为什么这件事值得做？

2026 年，大模型最缺的不是问答数据，而是"解决复杂问题的完整过程记录"。Codex 和 Claude Code 之所以能自动写代码、修 bug，不是因为它们看了更多代码，而是因为它们训练在了"程序员解决问题的完整轨迹"上——从发现 bug 到定位到修复的全过程。

我们要在 CV 科研领域做同样的事。而且我们有独特优势：CV 实验结果可以自动验证（mAP 涨了就是涨了），不需要人工标注。

2.2 四个人各扮演什么角色？

🔧 吴凡 — 实验室管理员

负责"实验室"的硬件环境：GPU 集群能跑、Docker 镜像能用、给任何 config 都能稳定返回实验结果。相当于保证实验室的仪器设备都是好的。

🧠 何天尧 — AI 研究员的大脑

负责造出那个"会自动做科研"的 Agent：它能思考、能写代码、能提交实验、能分析结果、能决定下一步做什么。同时负责把它的全过程忠实记录下来。

⚗️ 栗维鸿 — 数据炼金师

负责把 Agent 产出的"原始实验记录"提纯成"高质量教材"：过滤垃圾、修正 reward、转成训练格式、用这些数据训练 Qwen。相当于把原始矿石炼成黄金。

📋 负责人 — 考官

负责定义"什么叫做好"：出考试题（Benchmark）、判分（评测）、决定方向（这条路走不通就换）。从第一天就定义评测标准，不是最后才验收。

2.3 项目全流程一句话版

吴凡搭好实验室 → 何天尧造出 AI 研究员 → AI 研究员自动做实验 → 录制解题过程 → 栗维鸿提纯成教材 → 用教材训练 Qwen → 负责人考试验收

整个过程形成飞轮：考试发现弱点 → Agent 针对性补强 → 新一轮教材 → Qwen 更强

3.2 技术选型结论（CCG 三方验证 + 2026.05 框架调研）

推荐框架组合（2026 年 5 月最新验证）：

  • LangGraph v0.3 — 主编排框架（有状态 Agent、checkpoint、human-in-the-loop、失败恢复）
  • AIDE 式树搜索 — 实验策略（metric-driven pruning，将 mAP/mIoU 作为搜索信号）
  • MLAgentBench 式评测 — Benchmark 协议（端到端 ML 实验评测）
  • Ultralytics YOLO26 — 目标检测底座（57.6k stars，一站式检测/分割/分类，取代已停更的 MMDetection）
  • HuggingFace Transformers + Mask2Former — 语义分割底座（统一语义/实例/全景分割，取代已停更的 MMSegmentation）
  • ms-swift v4 — Qwen SFT/DPO 训练（阿里官方维护，Qwen 原生支持最佳，内置 Megatron 并行）
  • Weights & Biases — 实验追踪与可视化（sweep 超参搜索 + 团队协作）
  • DeepSpeed ZeRO-3 + FSDP2 — 64 卡分布式训练

⚠️ 技术栈更新说明（2026.05 调研结论）：

  • MMDetection 已停更（最后 release v3.3.0 = 2024.01，1.8k open issues 无人处理）→ 替换为 Ultralytics YOLO26
  • MMSegmentation 已停更（最后 release v1.2.2 = 2023.12）→ 替换为 HF Transformers + Mask2Former/SegFormer
  • LLaMA-Factory 仍可用（71.6k stars）但 ms-swift v4（阿里官方，2026.5.24 最新版）对 Qwen3 系列支持最佳
  • LangGraph 仍是最佳选择（33k stars，v0.3.15 = 2026.5.22），ML 科研 Agent 需要其复杂状态管理能力

4.1 Mock/Stub 解耦策略

为什么需要 Mock？

传统方式：吴凡搭完环境 → 何天尧才能开发 Agent → 栗维鸿才能做质检。这会导致前 4 周只有一个人在真正推进。

我们的方式：W1 就产出 Mock 数据，让下游提前开发。真实对接时只需替换数据源。

接口Mock 方Mock 内容何时替换真实
1a: experiment_spec.yaml何天尧3 个固定 spec（det/seg/tiny），hardcode 实验配置W4 吴凡服务 ready
1b: experiment_result.json何天尧预录制 3 种 result（成功/失败/超时）W4 真实对接
2: trajectory.jsonl栗维鸿何天尧 W2 产出 Schema 后，脚本生成 50 条合成轨迹W6 真实轨迹流入
3: model_manifest.yaml负责人栗维鸿给出 manifest 模板 + dummy checkpointW9 真实模型产出

7. 质量标准与验收机制

7.1 每次 Sprint 验收的四条卡口

  1. 能否一键复现？ — 任何人拉代码后能直接跑通
  2. 是否产生了真实轨迹数据？ — 不是只写了代码，而是有实际产出
  3. 是否有自动化指标？ — 不靠主观判断，有数字可看
  4. 是否有人审过样本质量？ — 至少抽检 10 条轨迹

7.2 数据入库门禁（三阶段）

阶段规则不通过则
语法校验代码编译/执行无致命错误标记为 invalid，不入训练集
步数校验3 步 ≤ 总步数 ≤ 30 步太短=无价值，太长=可能死循环
收益校验至少一次正向指标提升纯失败轨迹仅用于 DPO 负样本

7.3 评测目标量化定义

对标对象：Codex / Claude Code 在 CV 科研任务上的表现。我们的目标是让 Qwen-AutoResearch 在自建 Benchmark 上达到接近这些系统 70-80% 的水平。

指标含义目标
任务成功率完成有效改进的比例≥ 40%（Codex 级约 60%）
代码 Patch 成功率生成修改一次跑通率≥ 50%
诊断准确率失败原因判断正确率人类盲评胜率 > 55%
实验收益平均 mAP/mIoU 提升高于 base Qwen 30%+
资源效率达到相同提升的 GPU 小时低于 random search baseline

8.3 十条红线

  1. 不要把项目做成 CV 竞赛 — 核心产出是轨迹数据，不是 mAP 分数
  2. 只存结果不存过程 = 无效 — 没有 thought/action/observation 的数据不可训练
  3. 不允许各写各的日志格式 — 统一 Schema 第一天定死
  4. 不要过早追求复杂 Agent — 先单 Agent 跑通再迭代
  5. 实验必须可复现 — 种子/版本/config/数据全部入库
  6. 评估口径不能变 — 指标从第一周固定
  7. 每双周必须人工抽检轨迹 — 不抽检就会规模化制造垃圾
  8. 先定义模型要学什么行为，再采数据
  9. Agent 禁止写共享基线目录 — 只允许提交 patch/diff
  10. 遇到阻塞当天上报 — 不要等到双周 Review

用模拟数据代替真实接口，让下游在上游未就绪时仍能独立开发。本项目的核心并行化手段。
LangGraph
LangChain 出品的有状态 Agent 编排框架。支持 durable execution、checkpoint、人工接管。
AIDE（WecoAI）
将 ML 工程看作代码空间中的树搜索：每个节点是一个方案，metric 反馈驱动剪枝。
MLAgentBench
Stanford 出品的 ML Agent 评测框架。13 个端到端 ML 实验任务，评估 Agent 改进模型的能力。
轨迹 Schema
episode_id / task{domain, metric, goal, budget} / state / step{thought, action, observation, reward} / artifacts / labels
SFT（Supervised Fine-Tuning）
监督微调。用"任务→正确轨迹"对来训练模型。
DPO（Direct Preference Optimization）
偏好优化。同一任务给模型看"成功轨迹"和"失败轨迹"，学会区分好坏。
Sandbox（实验沙箱）
隔离容器环境。每次 Agent 实验在独立容器中运行，GPU quota + 超时 + 网络白名单，防止互相干扰。
Error-driven Synthesis
针对模型当前失败模式，专门生成对应训练数据。"哪里弱就补哪里"。
Smoke / Tiny / Full
多级实验：Smoke（5分钟验证代码能跑）→ Tiny（30分钟小数据验证方向）→ Full（完整训练）。
